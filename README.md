# SSC-and-SBOM-framework-
This project is a Software Supply Chain Security and SBOM Policy draft developed for a fictional bank. It addresses third party software risks, vendor risk assessment, SBOM validation, vulnerability management, exception handling, and regulatory and compliance mapping to establish a structured approach to software supply chain risk management. It build to devlop clear communication, regualtion compliance, and vendor managment.

# Objective
To establish a structured, clear, and deligence managment between vendor and organization, this document consist of policies that will address risk based approach to third-party software security that improves supply chain visibility, strengthens vulnerability management, and supports security governance and compliance.

# Project Type
Cybersecurity | Governance, Risk, and Compliance (GRC) | Software Supply Chain Risk Management

# Key Features
1) SBOM Management: Defines requirements for machine-readable SBOMs using CycloneDX or SPDX formats.
2) Vendor Risk Assessment: Classifies suppliers into risk tiers and establishes appropriate due diligence requirements.
3) Vulnerability Management: Establishes security scanning, severity-based remediation timelines, and vulnerability acceptance criteria.
4) Open-Source Governance: Addresses software licensing, dependency maintenance, and approved package sources.
5) Secure Deployment: Requires isolated sandbox testing and formal security approval before production deployment.
6) Exception Handling: Defines compensating controls when vendors cannot provide an SBOM.
7) Continuous Monitoring: Includes recurring SBOM updates, vulnerability monitoring, and vendor offboarding procedures.
8) Compliance Mapping: Maps policy controls to NIST SP 800-161, NIST SP 800-53, ISO/IEC 27001:2022, and relevant regulatory guidance.
